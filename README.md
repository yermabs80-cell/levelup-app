# Ethos Tracker

Трекер личного развития: квесты, ранги, четыре пути роста, финансы и помодоро-таймер.
PWA без сборки — обычные ES-модули, открывается в браузере как есть.

## Запуск

```bash
npm install
npm start          # http://localhost:4173
```

Открывать именно по `http://localhost`, а не двойным кликом по `index.html`.
Google запрещает вход со страниц `file://`, а модули и service worker там тоже не работают.

```bash
npm test           # 22 теста ядра
npm run lint
npm run icons      # перегенерировать PNG-иконки из геометрии icon.svg
```

## Как считается опыт

Опыт — **производная от журнала выполнений**, а не накопительный счётчик.
Каждая отметка пишется как `completions[дата][ключ квеста]`.

Отсюда три следствия:

- удалить квест и добавить заново не даёт повторный опыт — ключ за этот день уже занят;
- серия восстанавливается сама, даже если приложение не открывали;
- слияние двух устройств не удваивает опыт: одинаковые ключи схлопываются.

Одна завершённая сессия помодоро — 20 XP в дисциплину. Пропуск фазы опыта не даёт.

## Хранение

| Что | Где | Почему |
|---|---|---|
| Прогресс, квесты, финансы | localStorage | небольшой объём, синхронный доступ |
| Фотографии | IndexedDB | base64 переполнял квоту localStorage |
| Облачная копия прогресса | Firestore | один документ `users/{uid}` целиком |
| Облачная копия фотографий | Cloud Storage | base64 не влез бы в лимит документа 1 МиБ |

Повреждённый JSON не роняет приложение: старое значение сохраняется в резервный
ключ, а приложение стартует с чистого профиля.

Фотографии всегда рисуются из IndexedDB — он остаётся офлайн-кэшем. При входе в
аккаунт снимки в обе стороны догоняют друг друга: сделанные до входа уезжают в
`users/{uid}/photos/`, сделанные на другом устройстве — приезжают сюда.
Что уже залито, помнит отпечаток (`levelup-photo-sync`), поэтому перезагрузка
страницы не отправляет одни и те же файлы повторно.

## Синхронизация

Живая подписка `onSnapshot`: изменение на одном устройстве видно на другом сразу.
Конфликты разрешаются слиянием, а не «кто последний записал» — расхождение
системных часов не приводит к потере данных.

## Помодоро

Два режима: **25/5** и **50/10**. После четвёртой сессии — длинный перерыв.

Отсчёт ведётся от меток времени, а не вычитанием по тику: в фоновой вкладке
браузер душит таймеры до одного срабатывания в минуту, и наивный подход отстал бы
на десятки минут.

Пять фоновых звуков (дождь, лес, волны, ночь) синтезируются из шума прямо
в браузере — ни одного мегабайта загрузок, бесшовное зацикливание, работает офлайн.

Характер звука задаётся числами в `AMBIENT_CONFIG` наверху `src/data/ambient.js`:
частоты фильтров, `gain`, а также `rate`/`depth` медленного качания громкости.
Логику править не нужно — глуше дождь означает ниже `lowpass`, реже волны —
меньше `swell.rate`. Там же лежит комментарий, как подставить настоящие mp3,
если однажды понадобятся записи (и лицензия к ним).

## Иконки

`icon.svg` — источник истины. PNG для установки и Play Market собираются из той
же геометрии скриптом без зависимостей:

```bash
npm run icons
```

Он рисует `icons/icon-192.png`, `icons/icon-512.png` и
`icons/icon-maskable-512.png` (у maskable фон во всю площадь, а рисунок сжат до
78 %, чтобы Android не срезал углы щита) и кодирует PNG встроенным zlib.
Результат коммитится, поэтому у сборки по-прежнему нет зависимостей.

## Деплой

Cloudflare Workers раздаёт корень репозитория как статику (`wrangler.jsonc`,
`assets.directory: "./"`), а `.assetsignore` держит вне раздачи тесты, скрипты,
markdown и файлы правил Firebase.

Сборка идёт из ветки **main**: пока изменения не влиты в неё, живой сайт
показывает прежнюю версию, сколько бы коммитов ни лежало в рабочей ветке.

```bash
git push origin HEAD                      # рабочая ветка
git push origin HEAD:main                 # то, что реально попадёт на сайт
```

Кэш service worker версионируется вручную: правишь разметку — поднимай `CACHE`
в `sw.js` (`ethos-v12` → `v13`), иначе у уже установивших приложение останется
старый HTML.

## Выпуск в Play Market (TWA)

PWA заворачивается в Android-приложение через Trusted Web Activity: внутри
работает тот же сайт, но без адресной строки браузера.

```bash
npm install -g @bubblewrap/cli
bubblewrap init --manifest https://levelup-app.yermabs80.workers.dev/manifest.webmanifest
bubblewrap build          # → app-release-bundle.aab + подписанный ключ
```

Bubblewrap спросит applicationId (например `dev.workers.yermabs80.ethos`),
имя, цвета и создаст keystore. **Keystore и его пароль сохрани отдельно** —
без них обновить приложение в Play Market невозможно.

### assetlinks.json — обязательный шаг

Без него TWA откроется с адресной строкой, то есть как обычный браузер.
Файл связывает домен с подписью приложения:

```bash
bubblewrap fingerprint generateAssetLinks --output .well-known/assetlinks.json
```

Готовый файл должен отдаваться по адресу
`https://levelup-app.yermabs80.workers.dev/.well-known/assetlinks.json`
с `content-type: application/json`. Шаблон с пояснениями —
[`.well-known/assetlinks.json.example`](.well-known/assetlinks.json.example).

Проверить связку: `https://developers.google.com/digital-asset-links/tools/generator`.

> `not_found_handling: "single-page-application"` в `wrangler.jsonc` отдаёт
> `index.html` на любой неизвестный путь. Если файла нет, Android получит HTML
> вместо JSON и молча оставит адресную строку — так что после деплоя открой
> этот URL и убедись, что видишь JSON.

### Что не зависит от кода

- аккаунт разработчика Google Play — 25 $ единоразово;
- для новых аккаунтов обязательное закрытое тестирование: 12 тестировщиков
  в течение 14 дней до публикации;
- иконка в Play Console — отдельная загрузка 512×512 (подойдёт
  `icons/icon-512.png`), плюс feature graphic 1024×500 и скриншоты.

## Переименование воркера

Поддомен задаётся полем `name` в `wrangler.jsonc`. Смена имени создаёт **новый**
воркер: старый продолжает жить со старым URL, а новый домен нужно заранее
добавить в Firebase → Authentication → Authorized domains, иначе вход через
Google перестанет работать сразу после деплоя. Ссылки в README, манифесте и
командах Bubblewrap тоже придётся обновить — поэтому переименование делается
последним, когда всё остальное уже работает.

## Firebase

Настройка описана в [FIREBASE_SETUP.md](FIREBASE_SETUP.md).
Без конфига приложение работает локально, облачные функции просто отключены.

Правила доступа лежат в репозитории — [`firestore.rules`](firestore.rules) и
[`storage.rules`](storage.rules) — но применяются только вручную через консоль
Firebase. Автоматического деплоя правил здесь нет.
